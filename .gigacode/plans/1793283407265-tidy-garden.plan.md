# Implementation Plan: commitly — Git Task Manager

## Summary

Cross-platform task manager (Windows, macOS, iOS, Android, Web) using Flutter. **Hybrid Git integration**: REST API for cloud services (GitHub, GitLab, Gitea), libgit2 for self-hosted desktop. Markdown + JSON metadata. PAT authentication. Multi-device sync.

**Stack**: Flutter ^3.12.2, Riverpod, go_router, dio, flutter_secure_storage.

**File**: `lib/data/models/task.dart`

```dart
class Task {
  final int number;           // 1, 2, 3 → folder "001/"
  final String description;   // Markdown
  final String? assignee;
  final List<String> tags;
  final DateTime createdAt;
  final DateTime updatedAt;
  final String projectId;

  String get folderName => number.toString().padLeft(3, '0');
  String get descriptionPath => 'tasks/$folderName/description.md';
  String get metadataPath => 'tasks/$folderName/metadata.json';
}
```

## Phase 3: Git Service Layer

### 3.1. Abstract `GitService` interface
**File**: `lib/data/services/git_service.dart`

Core abstraction with methods:
- `initialize(config, pat)` — init with credentials
- `listRepositories()` — list user repos
- `listTaskNumbers(projectId)` — list task folders
- `readMetadata(projectId, taskNumber)` / `writeMetadata(...)` — metadata.json
- `readDescription(projectId, taskNumber)` / `writeDescription(...)` — description.md
- `listComments(projectId, taskNumber)` / `addComment(...)` / `deleteComment(...)`
- `uploadAttachment(...)` / `downloadAttachment(...)`
- `pull(projectId)` / `push(projectId)` / `checkConflicts(...)` / `resolveConflict(...)`
- `getNextTaskNumber(projectId)` / `getDefaultBranch(projectId)`

### 3.2. `RestApiGitService` — cloud implementation
**File**: `lib/data/services/rest_api_git_service.dart`

Uses `dio` with service-specific headers:
- **GitHub**: `Authorization: Bearer {pat}`, `Accept: application/vnd.github.v3+json`
- **GitLab**: `PRIVATE-TOKEN: {pat}`
- **Gitea**: `Authorization: Bearer {pat}`

API endpoints per service (GitHub pattern):
- `GET /repos/{owner}/{repo}/contents/tasks/{number}/description.md` — read
- `PUT /repos/{owner}/{repo}/contents/tasks/{number}/description.md` — write (base64 content + commit message)
- Same pattern for metadata.json, comments, attachments

### 3.3. `GitServiceFactory`
**File**: `lib/data/services/git_service_factory.dart`

```dart
class GitServiceFactory {
  static Future<GitService> create(GitServiceConfig config, String pat) {
    if (kIsWeb) return RestApiGitService(config, pat);
    // Desktop: could use libgit2 for self-hosted (future)
    return RestApiGitService(config, pat);
  }
}
```

## Phase 9: Sync & Conflict Resolution

### 9.1. Pull flow
1. Fetch latest metadata for all tasks from remote
2. Compare local timestamps with remote
3. No conflicts → update local state, return success
4. Conflicts → return `ConflictInfo` list

### 9.2. Conflict strategy
- **metadata.json**: Timestamp comparison. If different → prompt user
- **description.md**: Side-by-side diff, user merges
- **Comments**: Append-only, no conflicts

### 9.3. Conflict resolution UI
In `SyncStatusScreen`: list conflicted files → "Resolve" → detail view with local/remote panes + Accept Local / Accept Remote / Manual Merge buttons.

### 9.4. Auto-sync
On navigating to task list → auto pull.
